# The Maven wrapper script (mvnw)

## What it is

`mvnw` is a script (a text file of commands that a shell runs) that comes from the Apache Maven Wrapper project. When you type `./mvnw verify`, the script makes sure that exactly the Maven version this repository wants is on your machine, downloading it the first time, and then runs it with your arguments. The file is not written by this repository's author; it is generated by the wrapper tool and checked in unchanged, so it is quoted here in full and explained so that you know what runs on your machine when you use it.

A shell is the program that reads commands that you type, or that a script holds, and runs them. This script is for the POSIX shell, the common baseline of `sh`, `bash` and `zsh`, so it runs on macOS and Linux. The sibling file `mvnw.cmd` does the same job on Windows (see [the Windows batch note](windows-batch.md)).

## Why this repository uses it

Maven is a program that has to be installed. Different people have different versions, and a build can behave differently across versions. The wrapper removes the installation step and pins the version. The pinned version and the download address live in `.mvn/wrapper/maven-wrapper.properties`, which is explained in [Properties files](properties-files.md).

## Where it appears

| Path | Role |
| --- | --- |
| `mvnw` | this script, for macOS and Linux |
| `mvnw.cmd` | the Windows equivalent |
| `.mvn/wrapper/maven-wrapper.properties` | names the Maven download address (`distributionUrl`) |
| `~/.m2/wrapper/dists/...` (in your home folder, not in the repository) | where the downloaded Maven is kept, so the download happens once |

## How it works underneath

1. The script reads `distributionUrl` from the properties file.
2. It computes a folder name from the URL: a hash (a short fingerprint of the text, built the way Java's `String.hashCode` works) so that different URLs get different folders.
3. If that folder already exists, Maven is already installed: the script replaces itself with Maven (`exec`) and passes your arguments along.
4. Otherwise it downloads the archive with `wget`, or `curl`, or as a last resort a tiny Java program it writes and compiles on the spot. It checks the SHA-256 checksum if the properties file lists one, unpacks it into a temporary folder, moves it to the final folder, deletes the temporary folder, and then runs Maven.

Words used below: an *environment variable* is a named value that the operating system hands to every program it starts (for example `HOME`, your home folder). A *process* is a running program. `exec` replaces the running script by another program, so that no extra process is left waiting. A *checksum* is a fingerprint of a file; if one byte changes, the fingerprint changes.

### `mvnw`

The whole file, as it is in the repository:

```text
#!/bin/sh
# ----------------------------------------------------------------------------
# Licensed to the Apache Software Foundation (ASF) under one
# or more contributor license agreements.  See the NOTICE file
# distributed with this work for additional information
# regarding copyright ownership.  The ASF licenses this file
# to you under the Apache License, Version 2.0 (the

# KIND, either express or implied.  See the License for the
# specific language governing permissions and limitations
# under the License.
# ----------------------------------------------------------------------------

# ----------------------------------------------------------------------------
# Apache Maven Wrapper startup batch script, version 3.3.4
#
# Optional ENV vars
# -----------------
#   JAVA_HOME - location of a JDK home dir, required when download maven via java source
#   MVNW_REPOURL - repo url base for downloading maven distribution
#   MVNW_USERNAME/MVNW_PASSWORD - user and password for downloading maven
#   MVNW_VERBOSE - true: enable verbose log; debug: trace the mvnw script; others: silence the output
# ----------------------------------------------------------------------------

set -euf
[ "${MVNW_VERBOSE-}" != debug ] || set -x

# OS specific support.
native_path() { printf %s\\n "$1"; }
case "$(uname)" in
CYGWIN* | MINGW*)
  [ -z "${JAVA_HOME-}" ] || JAVA_HOME="$(cygpath --unix "$JAVA_HOME")"
  native_path() { cygpath --path --windows "$1"; }
  ;;
esac

# set JAVACMD and JAVACCMD
set_java_home() {
  # For Cygwin and MinGW, ensure paths are in Unix format before anything is touched
  if [ -n "${JAVA_HOME-}" ]; then
    if [ -x "$JAVA_HOME/jre/sh/java" ]; then
      # IBM's JDK on AIX uses strange locations for the executables
      JAVACMD="$JAVA_HOME/jre/sh/java"
      JAVACCMD="$JAVA_HOME/jre/sh/javac"
    else
      JAVACMD="$JAVA_HOME/bin/java"
      JAVACCMD="$JAVA_HOME/bin/javac"

      if [ ! -x "$JAVACMD" ] || [ ! -x "$JAVACCMD" ]; then
        echo "The JAVA_HOME environment variable is not defined correctly, so mvnw cannot run." >&2
        echo "JAVA_HOME is set to \"$JAVA_HOME\", but \"\$JAVA_HOME/bin/java\" or \"\$JAVA_HOME/bin/javac\" does not exist." >&2
        return 1
      fi
    fi
  else
    JAVACMD="$(
      'set' +e
      'unset' -f command 2>/dev/null
      'command' -v java
    )" || :
    JAVACCMD="$(
      'set' +e
      'unset' -f command 2>/dev/null
      'command' -v javac
    )" || :

    if [ ! -x "${JAVACMD-}" ] || [ ! -x "${JAVACCMD-}" ]; then
      echo "The java/javac command does not exist in PATH nor is JAVA_HOME set, so mvnw cannot run." >&2
      return 1
    fi
  fi
}

# hash string like Java String::hashCode
hash_string() {
  str="${1:-}" h=0
  while [ -n "$str" ]; do
    char="${str%"${str#?}"}"
    h=$(((h * 31 + $(LC_CTYPE=C printf %d "'$char")) % 4294967296))
    str="${str#?}"
  done
  printf %x\\n $h
}

verbose() { :; }
[ "${MVNW_VERBOSE-}" != true ] || verbose() { printf %s\\n "${1-}"; }

die() {
  printf %s\\n "$1" >&2
  exit 1
}

trim() {
  # MWRAPPER-139:
  #   Trims trailing and leading whitespace, carriage returns, tabs, and linefeeds.
  #   Needed for removing poorly interpreted newline sequences when running in more
  #   exotic environments such as mingw bash on Windows.
  printf "%s" "${1}" | tr -d '[:space:]'
}

scriptDir="$(dirname "$0")"
scriptName="$(basename "$0")"

# parse distributionUrl and optional distributionSha256Sum, requires .mvn/wrapper/maven-wrapper.properties
while IFS="=" read -r key value; do
  case "${key-}" in
  distributionUrl) distributionUrl=$(trim "${value-}") ;;
  distributionSha256Sum) distributionSha256Sum=$(trim "${value-}") ;;
  esac
done <"$scriptDir/.mvn/wrapper/maven-wrapper.properties"
[ -n "${distributionUrl-}" ] || die "cannot read distributionUrl property in $scriptDir/.mvn/wrapper/maven-wrapper.properties"

case "${distributionUrl##*/}" in
maven-mvnd-*bin.*)
  MVN_CMD=mvnd.sh _MVNW_REPO_PATTERN=/maven/mvnd/
  case "${PROCESSOR_ARCHITECTURE-}${PROCESSOR_ARCHITEW6432-}:$(uname -a)" in
  *AMD64:CYGWIN* | *AMD64:MINGW*) distributionPlatform=windows-amd64 ;;
  :Darwin*x86_64) distributionPlatform=darwin-amd64 ;;
  :Darwin*arm64) distributionPlatform=darwin-aarch64 ;;
  :Linux*x86_64*) distributionPlatform=linux-amd64 ;;
  *)
    echo "Cannot detect native platform for mvnd on $(uname)-$(uname -m), use pure java version" >&2
    distributionPlatform=linux-amd64
    ;;
  esac
  distributionUrl="${distributionUrl%-bin.*}-$distributionPlatform.zip"
  ;;
maven-mvnd-*) MVN_CMD=mvnd.sh _MVNW_REPO_PATTERN=/maven/mvnd/ ;;
*) MVN_CMD="mvn${scriptName#mvnw}" _MVNW_REPO_PATTERN=/org/apache/maven/ ;;
esac

# apply MVNW_REPOURL and calculate MAVEN_HOME
# maven home pattern: ~/.m2/wrapper/dists/{apache-maven-<version>,maven-mvnd-<version>-<platform>}/<hash>
[ -z "${MVNW_REPOURL-}" ] || distributionUrl="$MVNW_REPOURL$_MVNW_REPO_PATTERN${distributionUrl#*"$_MVNW_REPO_PATTERN"}"
distributionUrlName="${distributionUrl##*/}"
distributionUrlNameMain="${distributionUrlName%.*}"
distributionUrlNameMain="${distributionUrlNameMain%-bin}"
MAVEN_USER_HOME="${MAVEN_USER_HOME:-${HOME}/.m2}"
MAVEN_HOME="${MAVEN_USER_HOME}/wrapper/dists/${distributionUrlNameMain-}/$(hash_string "$distributionUrl")"

exec_maven() {
  unset MVNW_VERBOSE MVNW_USERNAME MVNW_PASSWORD MVNW_REPOURL || :
  exec "$MAVEN_HOME/bin/$MVN_CMD" "$@" || die "cannot exec $MAVEN_HOME/bin/$MVN_CMD"
}

if [ -d "$MAVEN_HOME" ]; then
  verbose "found existing MAVEN_HOME at $MAVEN_HOME"
  exec_maven "$@"
fi

case "${distributionUrl-}" in
*?-bin.zip | *?maven-mvnd-?*-?*.zip) ;;
*) die "distributionUrl is not valid, must match *-bin.zip or maven-mvnd-*.zip, but found '${distributionUrl-}'" ;;
esac

# prepare tmp dir
if TMP_DOWNLOAD_DIR="$(mktemp -d)" && [ -d "$TMP_DOWNLOAD_DIR" ]; then
  clean() { rm -rf -- "$TMP_DOWNLOAD_DIR"; }
  trap clean HUP INT TERM EXIT
else
  die "cannot create temp dir"
fi

mkdir -p -- "${MAVEN_HOME%/*}"

# Download and Install Apache Maven
verbose "Couldn't find MAVEN_HOME, downloading and installing it ..."
verbose "Downloading from: $distributionUrl"
verbose "Downloading to: $TMP_DOWNLOAD_DIR/$distributionUrlName"

# select .zip or .tar.gz
if ! command -v unzip >/dev/null; then
  distributionUrl="${distributionUrl%.zip}.tar.gz"
  distributionUrlName="${distributionUrl##*/}"
fi

# verbose opt
__MVNW_QUIET_WGET=--quiet __MVNW_QUIET_CURL=--silent __MVNW_QUIET_UNZIP=-q __MVNW_QUIET_TAR=''
[ "${MVNW_VERBOSE-}" != true ] || __MVNW_QUIET_WGET='' __MVNW_QUIET_CURL='' __MVNW_QUIET_UNZIP='' __MVNW_QUIET_TAR=v

# normalize http auth
case "${MVNW_PASSWORD:+has-password}" in
'') MVNW_USERNAME='' MVNW_PASSWORD='' ;;
has-password) [ -n "${MVNW_USERNAME-}" ] || MVNW_USERNAME='' MVNW_PASSWORD='' ;;
esac

if [ -z "${MVNW_USERNAME-}" ] && command -v wget >/dev/null; then
  verbose "Found wget ... using wget"
  wget ${__MVNW_QUIET_WGET:+"$__MVNW_QUIET_WGET"} "$distributionUrl" -O "$TMP_DOWNLOAD_DIR/$distributionUrlName" || die "wget: Failed to fetch $distributionUrl"
elif [ -z "${MVNW_USERNAME-}" ] && command -v curl >/dev/null; then
  verbose "Found curl ... using curl"
  curl ${__MVNW_QUIET_CURL:+"$__MVNW_QUIET_CURL"} -f -L -o "$TMP_DOWNLOAD_DIR/$distributionUrlName" "$distributionUrl" || die "curl: Failed to fetch $distributionUrl"
elif set_java_home; then
  verbose "Falling back to use Java to download"
  javaSource="$TMP_DOWNLOAD_DIR/Downloader.java"
  targetZip="$TMP_DOWNLOAD_DIR/$distributionUrlName"
  cat >"$javaSource" <<-END
	public class Downloader extends java.net.Authenticator
	{
	  protected java.net.PasswordAuthentication getPasswordAuthentication()
	  {
	    return new java.net.PasswordAuthentication( System.getenv( "MVNW_USERNAME" ), System.getenv( "MVNW_PASSWORD" ).toCharArray() );
	  }
	  public static void main( String[] args ) throws Exception
	  {
	    setDefault( new Downloader() );
	    java.nio.file.Files.copy( java.net.URI.create( args[0] ).toURL().openStream(), java.nio.file.Paths.get( args[1] ).toAbsolutePath().normalize() );
	  }
	}
	END
  # For Cygwin/MinGW, switch paths to Windows format before running javac and java
  verbose " - Compiling Downloader.java ..."
  "$(native_path "$JAVACCMD")" "$(native_path "$javaSource")" || die "Failed to compile Downloader.java"
  verbose " - Running Downloader.java ..."
  "$(native_path "$JAVACMD")" -cp "$(native_path "$TMP_DOWNLOAD_DIR")" Downloader "$distributionUrl" "$(native_path "$targetZip")"
fi

# If specified, validate the SHA-256 sum of the Maven distribution zip file
if [ -n "${distributionSha256Sum-}" ]; then
  distributionSha256Result=false
  if [ "$MVN_CMD" = mvnd.sh ]; then
    echo "Checksum validation is not supported for maven-mvnd." >&2
    echo "Please disable validation by removing 'distributionSha256Sum' from your maven-wrapper.properties." >&2
    exit 1
  elif command -v sha256sum >/dev/null; then
    if echo "$distributionSha256Sum  $TMP_DOWNLOAD_DIR/$distributionUrlName" | sha256sum -c - >/dev/null 2>&1; then
      distributionSha256Result=true
    fi
  elif command -v shasum >/dev/null; then
    if echo "$distributionSha256Sum  $TMP_DOWNLOAD_DIR/$distributionUrlName" | shasum -a 256 -c >/dev/null 2>&1; then
      distributionSha256Result=true
    fi
  else
    echo "Checksum validation was requested but neither 'sha256sum' or 'shasum' are available." >&2
    echo "Please install either command, or disable validation by removing 'distributionSha256Sum' from your maven-wrapper.properties." >&2
    exit 1
  fi
  if [ $distributionSha256Result = false ]; then
    echo "Error: Failed to validate Maven distribution SHA-256, your Maven distribution might be compromised." >&2
    echo "If you updated your Maven version, you need to update the specified distributionSha256Sum property." >&2
    exit 1
  fi
fi

# unzip and move
if command -v unzip >/dev/null; then
  unzip ${__MVNW_QUIET_UNZIP:+"$__MVNW_QUIET_UNZIP"} "$TMP_DOWNLOAD_DIR/$distributionUrlName" -d "$TMP_DOWNLOAD_DIR" || die "failed to unzip"
else
  tar xzf${__MVNW_QUIET_TAR:+"$__MVNW_QUIET_TAR"} "$TMP_DOWNLOAD_DIR/$distributionUrlName" -C "$TMP_DOWNLOAD_DIR" || die "failed to untar"
fi

# Find the actual extracted directory name (handles snapshots where filename != directory name)
actualDistributionDir=""

# First try the expected directory name (for regular distributions)
if [ -d "$TMP_DOWNLOAD_DIR/$distributionUrlNameMain" ]; then
  if [ -f "$TMP_DOWNLOAD_DIR/$distributionUrlNameMain/bin/$MVN_CMD" ]; then
    actualDistributionDir="$distributionUrlNameMain"
  fi
fi

# If not found, search for any directory with the Maven executable (for snapshots)
if [ -z "$actualDistributionDir" ]; then
  # enable globbing to iterate over items
  set +f
  for dir in "$TMP_DOWNLOAD_DIR"/*; do
    if [ -d "$dir" ]; then
      if [ -f "$dir/bin/$MVN_CMD" ]; then
        actualDistributionDir="$(basename "$dir")"
        break
      fi
    fi
  done
  set -f
fi

if [ -z "$actualDistributionDir" ]; then
  verbose "Contents of $TMP_DOWNLOAD_DIR:"
  verbose "$(ls -la "$TMP_DOWNLOAD_DIR")"
  die "Could not find Maven distribution directory in extracted archive"
fi

verbose "Found extracted Maven distribution directory: $actualDistributionDir"
printf %s\\n "$distributionUrl" >"$TMP_DOWNLOAD_DIR/$actualDistributionDir/mvnw.url"
mv -- "$TMP_DOWNLOAD_DIR/$actualDistributionDir" "$MAVEN_HOME" || [ -d "$MAVEN_HOME" ] || die "fail to move MAVEN_HOME"

clean || :
exec_maven "$@"
```


Reading it, block by block (line numbers refer to the listing above, counting the license comment at the top):

1. Lines 1 to 19: the first line, `#!/bin/sh`, is the shebang. It tells the operating system which program runs the file. The rest is the Apache license text in comments; a line starting with `#` is ignored by the shell. Lines 21 to 30 are comments that describe the version and the environment variables you may set: `JAVA_HOME` (where a JDK is installed), `MVNW_REPOURL` (a different place to download from), `MVNW_USERNAME` and `MVNW_PASSWORD` (credentials for a download that needs a login) and `MVNW_VERBOSE` (`true` prints what the script does, `debug` prints every command).
2. Line 32, `set -euf`, sets three safety switches: `-e` stop at the first failing command, `-u` treat a variable that was never set as an error, `-f` switch off filename expansion (the use of `*` as a wildcard). Line 33: `"${MVNW_VERBOSE-}"` is the value of the variable or an empty text when it is unset; if it is not `debug`, the `||` (or) is not needed and nothing happens, else `set -x` switches on tracing, which prints each command before running it.
3. Lines 35 to 42: a function `native_path` is defined that prints its argument unchanged (`printf %s\n "$1"`). On Windows-like shells (Cygwin or MinGW, found with `uname`, which prints the operating system name) the `JAVA_HOME` is first converted from Windows to Unix style with `cygpath`, and `native_path` is redefined to convert paths back to the Windows style. On macOS and Linux this block changes nothing.
4. Lines 44 to 79: the function `set_java_home` finds the Java commands. If `JAVA_HOME` is set, it uses `$JAVA_HOME/bin/java` and `javac` (a special place on IBM's AIX system is tried first), and prints an error and returns 1 (failure) if the files are not executable (`-x` tests that). If `JAVA_HOME` is not set, it asks the shell where `java` and `javac` are with `command -v`; the quoting `'set' +e` and `'unset' -f command` protect against a user having redefined those words. If still not found, it prints an error. The `>&2` sends a message to standard error, the channel for errors.
5. Lines 81 to 90: the function `hash_string` computes a number from text in the same way Java does: it loops over the characters, and for each one sets `h` to `h * 31 + the character code`, kept below 2 to the power 32 with `% 4294967296`. `${str%"${str#?}"}` is a shell trick to take the first character and `${str#?}` removes it. At the end the number is printed in hexadecimal (`%x`).
6. Lines 92 to 106: small helpers. `verbose` does nothing (`:` is the do-nothing command) unless `MVNW_VERBOSE` is `true`, in which case it prints its argument. `die` prints a message to standard error and ends the script with status 1. `trim` removes all whitespace from a text with `tr -d '[:space:]'`, which fixes stray carriage returns on Windows.
7. Lines 108 to 118: `scriptDir` and `scriptName` store the folder and the file name of the script (`dirname`, `basename`; `$0` is how the script was called). The `while` loop reads the properties file line by line: `IFS="=" read -r key value` splits each line at the first `=` into `key` and `value`; the `case` stores the two keys it knows (`distributionUrl`, `distributionSha256Sum`) after trimming. `done <"$scriptDir/.mvn/wrapper/maven-wrapper.properties"` feeds the file to the loop. Line 118 stops with a message if no URL was found.
8. Lines 120 to 137: a `case` looks at the file name part of the URL (`${distributionUrl##*/}` removes everything up to the last `/`). If it is a `maven-mvnd-...` name (Maven Daemon, a faster alternative), the script picks the platform from `uname` and builds the URL accordingly; otherwise (our case) `MVN_CMD` is `mvn` plus whatever follows `mvnw` in the script's name, and the repository pattern is `/org/apache/maven/`.
9. Lines 139 to 146: if `MVNW_REPOURL` is set, the beginning of the URL is replaced to point at that mirror. Then names are computed: `distributionUrlName` is the file name, `distributionUrlNameMain` the same without the extension and without `-bin`. `MAVEN_USER_HOME` defaults to `~/.m2` (`${HOME}/.m2`). `MAVEN_HOME`, the folder where this Maven version lives, becomes `<MAVEN_USER_HOME>/wrapper/dists/<name>/<hash of the URL>`.
10. Lines 148 to 156: `exec_maven` forgets the wrapper's own variables (`unset`) and replaces the script with `$MAVEN_HOME/bin/$MVN_CMD "$@"` (`"$@"` means every argument you gave, each kept as one piece); it ends the script with a message if the exec fails. If `MAVEN_HOME` already exists, the script runs Maven now (lines 153 to 156); everything after that is only for the first run.
11. Lines 158 to 161: checks that the URL ends in `-bin.zip` (or looks like an mvnd zip); otherwise stops with an explanation. Lines 163 to 169: creates a temporary folder with `mktemp -d`, and registers a clean-up function with `trap clean HUP INT TERM EXIT`, which means: delete the folder when the script ends or is interrupted. Line 171: creates the parent folder of `MAVEN_HOME` (`mkdir -p` also creates missing parents). Lines 173 to 176: verbose messages.
12. Lines 178 to 182: if there is no `unzip` program, switch to the `.tar.gz` form of the archive. Lines 184 to 186: set the quietness options of `wget`, `curl`, `unzip` and `tar`, and clear them when verbose.
13. Lines 188 to 192: normalizes the login: the password counts only if a username is also given, otherwise both are emptied. `${VAR:+text}` gives `text` only if the variable is set and not empty.
14. Lines 194 to 223: the download. If there is no username and `wget` exists, use it (`-O` names the output file); `die` runs if it fails (`|| die ...`). Else, if `curl` exists, use it (`-f` fail on HTTP errors, `-L` follow redirects, `-o` output file). Else, `set_java_home` finds Java, and the script writes a small Java program to a file with a here-document: `cat >"$javaSource" <<-END ... END` copies the lines up to `END` into the file (the `-` lets the lines start with tabs). That program, `Downloader`, copies the content of the URL into a file, with the user name and password if needed. The script compiles it with `javac` and runs it with `java -cp`. `native_path` converts the paths on Windows-like shells.
15. Lines 225 to 250: if the properties file has a checksum, verify the archive. mvnd is rejected because it is not supported. Else `sha256sum -c` (Linux) or `shasum -a 256 -c` (macOS) compares the file against the expected fingerprint; the result goes into `distributionSha256Result`. If it is not true, the script prints that the download may be compromised and exits with status 1. If neither tool exists, it tells you to install one.
16. Lines 252 to 257: unpack the archive into the temporary folder with `unzip -d` (or `tar xzf ... -C` for the `.tar.gz`).
17. Lines 259 to 288: find the unpacked folder. First try the expected name; if it holds `bin/mvn`, use it. Otherwise (for snapshot builds whose folder name differs) turn globbing back on (`set +f`), loop over every folder in the temporary directory with `for dir in "$TMP_DOWNLOAD_DIR"/*`, take the first that holds `bin/mvn`, and turn globbing off again (`set -f`). If none is found, print the folder listing (verbose) and stop.
18. Lines 290 to 295: write the URL into a file `mvnw.url` inside the unpacked folder (a note of where it came from), move the unpacked folder to `MAVEN_HOME` with `mv` (if the move fails but the folder now exists, because another run finished first, that is fine), call `clean` to delete the temporary folder, and finally `exec_maven "$@"` runs Maven with your arguments.

## Try it yourself

1. Run `./mvnw -v`. The first time it downloads Maven, then prints Maven's version and the Java it found.
2. Run it with `MVNW_VERBOSE=true ./mvnw -v` and read the messages. They match the steps above.
3. Look in `~/.m2/wrapper/dists` and find the folder named after the Maven version, with a hash folder inside it.
4. Open `.mvn/wrapper/maven-wrapper.properties` and find the `distributionUrl` line the script reads.

## Mistakes people make

- Editing `mvnw` by hand. Regenerate it with the wrapper tool instead, so it stays in step with the properties file.
- Forgetting `chmod +x mvnw`. Git keeps the executable bit when it was committed; if you see "permission denied", run `chmod +x mvnw`.
- Running behind a company proxy and blaming Maven: the failure is the download step, so `curl` or `wget` need the proxy settings.
- Removing the checksum line from the properties file to silence a mismatch. The mismatch means the download is not the file the author tested.

## Check yourself

1. Where is the downloaded Maven kept? *Under `~/.m2/wrapper/dists`, in a folder named after the distribution and a hash of its URL.*
2. Which tools can it download with? *`wget`, then `curl`, then a small Java program.*
3. Why does it compute a hash? *So that two different URLs never share one folder.*
4. What does `exec` do at the end? *It replaces the script by Maven, so Maven's exit code becomes the script's.*
